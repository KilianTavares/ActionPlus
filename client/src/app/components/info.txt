Server components: 
- Components that never run on the client. They are pre rendered and sent to the client.
- Server Components are rendered into a special data format called the React Server Component Payload (RSC Payload).
- Great for things like fetching data from a database, reading files, or doing secure operations.

Use Server Components when you need:

Fetch data from databases or APIs close to the source.
Use API keys, tokens, and other secrets without exposing them to the client.
Reduce the amount of JavaScript sent to the browser.
Improve the First Contentful Paint (FCP), and stream content progressively to the client.

✅ Benefits:
- Fast initial load: HTML is pre-rendered.
- Smaller bundle size: No JavaScript sent to the browser for these components.
- Secure: Sensitive logic stays on the server.

Client components: 
- These components are hydrated in the browser with JavaScript.
✅ Benefits:
- Can use hooks like useState, useEffect, useContext.
- Can respond to user actions in real time.

❌ Client Components are not SSR-ed
- Client Components are hydrated in the browser — they don’t benefit from SSR directly.
- You can include Client Components inside SSR pages, but they themselves are not server-rendered.
- They rely on JavaScript to become interactive after the HTML is delivered.


🧩 SSR (Server-Side Rendering) is used with Server Components, not Client Components.
✅ Server Components + SSR
- SSR means the HTML is generated on the server at request time.
- Server Components are naturally SSR-compatible because they run on the server.
- You use SSR when you need fresh data on every request (e.g., user-specific dashboards, real-time listings).

🔄 How They Work Together
You can mix both in a page:
- The outer layout and data-fetching logic can be Server Components (SSR).
- The interactive parts (like filters, buttons, modals) are Client Components.
This hybrid model is what makes Next.js App Router so powerful.
